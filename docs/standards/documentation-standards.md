# Documentation Standards

Code tells you _how_ a system works; documentation tells you _why_.

## General Principles

- **Keep it close to the code**: Documentation should live in the same repository as the code it describes.
- **Avoid Duplication**: Link to existing documentation (like this handbook) rather than copying text.
- **Keep it Updated**: Update documentation in the same PR that changes the code.

## Architectural Decision Records (ADRs)

For significant changes, use ADRs to capture context. See our [ADR Guidelines](../architecture/adr/README.md).
